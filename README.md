# Omar Elmetwalli — research portfolio

Personal academic site: physics-informed ML for turbulence, CFD, PIV, and flow control.
Live at **https://omar-elmetwalli.github.io/github-portfolio/**

Next.js 16 (App Router) · React 19 · Tailwind CSS v4 · TypeScript · static export on GitHub Pages · optional AI assistant on a Cloudflare Worker.

## Run locally

Requires Node 22.18+ and pnpm 10.

```bash
pnpm install
pnpm dev          # http://localhost:3000 (no base path in dev)
```

To check the real static site the way GitHub Pages serves it:

```bash
pnpm build
pnpm preview      # http://localhost:4173/github-portfolio/
```

| Command | What it does |
| --- | --- |
| `pnpm dev` | Dev server |
| `pnpm build` | Static export to `out/` (also writes `sitemap.xml`, `robots.txt`, link-preview images, and `ai/knowledge.json`) |
| `pnpm preview` | Serves `out/` under `/github-portfolio/` with gzip, like GitHub Pages |
| `pnpm lint` / `pnpm typecheck` | ESLint / TypeScript |
| `pnpm check:links` | Fails on any broken internal link, anchor, PDF, or image in `out/` (add `-- --external` to also check external links) |
| `pnpm test:e2e:build` then `pnpm test:e2e` | Playwright smoke tests (desktop + mobile) against a build with the AI endpoint mocked |
| `pnpm worker:test` | AI worker tests (mocked, no API calls) |
| `pnpm optimize:images` | Converts new PNG/JPG in `public/images` to WebP and refreshes `data/media.json` |
| `pnpm ai:summaries` | Generates plain-language project overviews (local, needs an API key) |
| `pnpm career …` | Private career tools (local only, see below) |
| `node scripts/screenshots.mjs` | Light/dark screenshots at 360/768/1280 px into `screenshots/` |

## Admin (edit everything from a browser)

```bash
pnpm admin        # http://localhost:4321
pnpm dev          # (optional, second terminal) live preview at http://localhost:3000
```

A local editor that runs only on your computer (it is not part of the website):

- **Projects:** add, edit, reorder, or delete. Categories, featured/confidential, sections, links, and drag-and-drop uploads for figures, photos, videos, and report PDFs. PNG/JPG are converted to WebP automatically.
- **Profile & research, Experience & CV, Leadership, Awards, Publications, Plain summaries:** form editors for every field, with add/remove/reorder for lists and upload buttons for file paths.
- **Uploads:** put any file into `public/` (e.g. a new CV PDF) and copy its path.
- **Save** (Ctrl+S) validates first (unique slugs, valid categories, files that exist) and writes `data/content/*.json`.
- **Check site** runs typecheck, build, and the link checker.
- **Publish** commits `data/` and `public/` and pushes to GitHub, which redeploys the live site.

## Editing content

All content lives in `data/content/*.json` (edit with `pnpm admin`, or by hand). The `data/*.ts` files are typed wrappers around it. Components never hard-code content.

| File | Holds |
| --- | --- |
| `data/content/profile.json` | Name, tagline, availability badge, emails, bio, research interests, collaborations, stats, skills, education |
| `data/content/projects.json` | Projects (cards, project pages, AI knowledge base) |
| `data/content/publications.json` | Publications (the section appears once this list has entries) |
| `data/content/awards.json` | Awards and honors |
| `data/content/resume.json` | Experience, certifications, technical skills, languages, CV PDF path |
| `data/content/leadership.json` | AIAA branch role and its photo/video gallery (with captions) |
| `data/summaries.json` | Plain-language overviews for the Overview/Technical switch |
| `data/media.json` | Image sizes (generated by `pnpm optimize:images`) |

### Add a project

1. Put images in `public/images/projects/<slug>/` and run `pnpm optimize:images` (converts to WebP, kebab-case names).
2. Put any PDF in `public/files/`.
3. Add it in `pnpm admin`, or add an entry to `data/content/projects.json`:

```ts
{
  "slug": "my-new-project",                      // URL: /projects/my-new-project/
  "categories": ["Fluid Mechanics & CFD"],        // drives the filters; values from CATEGORIES
  "title": "…",
  "date": "2026-11",
  "tags": ["CFD", "LES"],
  "tools": ["OpenFOAM", "Python"],
  "summary": "One paragraph. Inline math works: $Re = 10^5$.",
  "sections": [{ "title": "Method", "content": "…" }],
  "links": { "paper": "/files/my-report.pdf", "github": "https://github.com/…" },
  "gallery": ["/images/projects/my-new-project/result.webp"]
}
```

Optional fields: `"featured": true` shows it under *Selected research*; `"confidential": true` plus `"publicSummary": "…"` publishes only that summary (the detailed text never reaches the browser or the AI). Projects without images get a generated cover.

Math: write LaTeX between `$…$`. In the admin, type it as-is (`$\omega_n$`); in the raw JSON file, backslashes are doubled (`$\\omega_n$`). A literal dollar sign is `\$`.

### Add a publication

```ts
{
  title: "…",
  authors: ["A. Hamada", "O. Elmetwalli", "M. Ayyad"],
  status: "Under review",          // "In preparation" | "Under review" | "Preprint" | "Published"
  venue: "Journal of Fluid Mechanics",
  year: "2027",
  doi: "10.xxxx/…",                 // optional, also pdf / arxiv
  project: "ml-augmented-turbulence-modeling",
}
```

### Add an award

```ts
{ title: "…", issuer: "…", date: "2026", description: "optional" }
```

### Plain-language overviews (Overview/Technical switch)

```bash
pnpm ai:summaries                 # writes new entries to data/summaries.json
pnpm ai:summaries -- --only <slug>
```

Each entry starts as `"reviewed": false`. Read it, edit the text if needed, and set `"reviewed": true` to publish it. Projects without a reviewed overview don't show the switch.

## AI assistant

GitHub Pages is static, so AI calls go through a small Cloudflare Worker in [`ai-worker/`](ai-worker/README.md) that holds the API key. It powers the chat ("Ask Omar's AI"), the fit check, and the command palette's "Ask AI about…".

- Answers are grounded in `/ai/knowledge.json`, which `pnpm build` generates from `data/`. Confidential projects contribute only their `publicSummary`.
- The worker enforces a CORS allow-list, 20 questions per IP per hour, input and output limits, a server-side system prompt, and a Cloudflare Turnstile check on first use.
- If `NEXT_PUBLIC_AI_ENDPOINT` isn't set, every AI element is hidden and the rest of the site works normally.

**Deploy the worker:** follow [ai-worker/README.md](ai-worker/README.md) (`wrangler login`, create the KV namespace, `wrangler secret put …`, `wrangler deploy`), then add the worker URL and Turnstile site key as GitHub repository variables.

## Environment variables

Site (set as GitHub **repository variables** for deploys, or in `.env.local` locally; see `.env.example`):

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_AI_ENDPOINT` | AI worker URL. Unset = AI features hidden |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Cloudflare Turnstile site key (public) |
| `NEXT_PUBLIC_WEB3FORMS_KEY` | Contact form delivery. Unset = form opens the visitor's email app |
| `NEXT_PUBLIC_GOATCOUNTER_CODE` | Privacy-friendly analytics (production only) |

Local scripts only (`.env.local`, never shipped): `AI_PROVIDER` (`gemini` / `anthropic` / `openai` / `mock`), `AI_MODEL`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`.

Worker (`wrangler.toml` vars and `wrangler secret put`): `AI_PROVIDER`, `AI_MODEL`, `ALLOWED_ORIGINS`, `KNOWLEDGE_URL`, `RATE_LIMIT_PER_HOUR`, `MAX_INPUT_CHARS`, `MAX_FIT_INPUT_CHARS`, `MAX_OUTPUT_TOKENS`, secrets `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`, `SESSION_SECRET`, `TURNSTILE_SECRET`, and the `RATE_LIMIT` KV binding.

## Deployment

Pushing to `main` runs `.github/workflows/nextjs.yml`:

1. **checks**: lint, typecheck, AI worker typecheck and tests
2. **e2e**: build with a mocked AI endpoint, link check, Playwright smoke tests
3. **build**: production build with the repository variables, link check again
4. **deploy**: publish `out/` to GitHub Pages (only if everything above passed)

Pull requests run steps 1–3 without deploying.

## Private career tools

Resume tailoring, cover letters, and job-fit notes run locally and are never part of the website:

```bash
pnpm career tailor --job posting.txt --role "CFD Engineer"
pnpm career cover-letter --job posting.txt --company "Acme Aero" --role "R&D Engineer"
pnpm career fit --job posting.txt
```

Output is saved to `career-output/` (git-ignored). Needs the worker's dependencies once: `pnpm --dir ai-worker install`.

